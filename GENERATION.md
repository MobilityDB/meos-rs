# meos-rs generation — the canonical per-binding generator policy

meos-rs is a **generated** binding. This document is the contract for how it is generated,
under the ecosystem-wide per-binding generator policy.

## The policy (ecosystem-wide)

Every MobilityDB language binding is a **pure projection of the MEOS-API catalog**, and
**each binding owns its own generator, in its own repo**, in a canonical layout. The single
source of truth is the **catalog** (`MEOS-API/output/meos-idl.json`, generated from the MEOS
C headers). This mirrors how MEOS itself is built: independent, plug-and-play, CMake-gated
families — a binding is an independent module that owns its generation.

Each binding repo satisfies the same invariants: in-repo generator; own
`tools/pin/compose-order.txt`; vendored/pinned catalog input; thin language projection
(language-neutral decisions live in the catalog); full automation toward a zero-hand-written
surface (generate-then-retire; the last green-CI version is the equivalence probe).

## Current state and the canonical target

**Today** the `meos-sys` FFI is generated by **bindgen** (`sys/build.rs` `#[cfg(feature =
"bindgen")]` over `sys/wrapper.h`), with committed `sys/prebuilt-bindings/meos_{1.1,1.2,1.3}.rs`
for builds without bindgen. The MEOS source is a git submodule (`sys/meos-src/source`).

**The target** (per the North Star, to keep **one** generation logic across all bindings
instead of a Rust-specific one) is to generate `meos-sys` from the same **`meos-idl.json`
catalog** as every other binding. bindgen and the catalog read the *same* `meos/include`
headers, so the surface is equivalent; the catalog additionally carries enrichment bindgen
cannot express — portable bare-name aliases, canonical names, output/array/nullability
shape, and recovered collapsed types (`bool`/`int64`/`Timestamp` that the C preprocessor
flattens to `int`). A catalog-generated binding is therefore **cleaner** (MEOS values are
opaque pointers — e.g. geometry as `GSERIALIZED*` — so the transitive liblwgeom/glibc struct
layouts bindgen emits are simply not exposed) and **more correct**.

## Migration: generate-then-retire (non-disruptive)

1. add a `meos-idl.json` -> Rust generator (the `meos-sys` extern + opaque-type layer),
   alongside bindgen — do not remove bindgen;
2. **prove equivalence**: the catalog-generated FFI is ABI-equivalent to
   `sys/prebuilt-bindings/*.rs` (function set ⊇, opaque types, the consts/flags) and the
   crate + examples build and run green;
3. close gaps **at source**: any public symbol the catalog under-models (notably the public
   `#define` constants/flags — bindgen emits ~149, the catalog ~20 enums) is added to the
   **MEOS-API catalog**, never hand-written in Rust, so every binding gains it;
4. **then** retire bindgen and the prebuilt-bindings. End state: meos-rs is a catalog
   projection like the rest — one generation logic to maintain.

## Pinning

The MEOS surface is pinned via the `sys/meos-src/source` submodule. It should track an
**immutable MobilityDB `ecosystem-pin-*` commit** (not the moving `stable-1.3` branch) and
bump to 1.4, so the surface matches the catalog the generator consumes. See
`tools/pin/compose-order.txt`.
